# 形状范围筛选 · Eagle Shape Range

**[English](README.en.md)** ｜ 简体中文

一个 [Eagle](https://eagle.cool) 插件:**按「近似形状 / 长宽比区间 / 文件类型」筛选素材**。

Eagle 原生的形状筛选只有精确匹配 —— 「方形」要求 `width === height`,「4:3」「16:9」要求比值浮点精确相等 ——
没有容差,也没有长宽比区间。本插件补上这个缺口:近似方形、任意目标比例 ± 容差、长宽比区间,
并可结合按文件类型的筛选。

> 只想快速上手:从 [**Releases**](../../releases) 下载 `.eagleplugin` 双击安装,
> 或把 `eagle-shape-range` 整个文件夹放进 `%APPDATA%\Eagle\Plugins\`。

---

## 一、问题:原生形状筛选有多严格

判定逻辑写死在 Eagle 本体里(`app/js/rule-match.js` → `isMatchShapeRule`):

- **方形** 要求 `width === height`,差 1 像素就掉进「横图 / 竖图」
- **横图 / 竖图 / 细长横图 / 细长竖图** 是按比值 **2.5** 一刀切出的四档
- **4:3 / 3:4 / 16:9 / 9:16 / 自定** 都是比值**浮点精确相等** —— `1025×768` 就不命中 `4:3`

在一份约 6 万条的真实素材库上做全量统计(58,445 条含尺寸):

| 条件 | 原生能筛到 | 本插件(容差 5%) | 多出 |
|---|---|---|---|
| 方形(1:1) | **815** | **1,175** | +360(1.44x) |
| 16:9 | **1,772** | **3,466** | +1,694(**1.96x**) |

被原生归为「竖图 / 横图」、而人眼完全就是正方形的真实例子:

| 尺寸 | 比例 | 原生分类 |
|---|---|---|
| 3413 × 3430 | 0.9950 | portrait |
| 2024 × 2040 | 0.9922 | portrait |
| 2003 × 2048 | 0.9780 | portrait |
| 3000 × 2933 | 1.0228 | landscape |
| 2640 × 2615 | 1.0096 | landscape |

**为什么不做成原生选项?** 因为插件 API 无法扩展 Eagle 的筛选面板,而直接修改 `app.asar`
会被 Eagle 自身的防篡改校验拦下(启动时校验 `app.bundle.js`)。这两条路的具体证据、
以及误改之后的恢复方法,都记在 [`docs/native-filter-findings.md`](docs/native-filter-findings.md)。

## 二、功能

**筛选条件**

| | |
|---|---|
| 近似比例 | 目标比例(1:1 / 4:3 / 3:4 / 3:2 / 2:3 / 16:9 / 9:16 / 2:1 / 1:2 / 自定义 W:H)± 容差百分比 |
| 长宽比区间 | 直接给最小 / 最大长宽比,例如 `1.2 – 1.4` |
| 方向 | 横竖均可 / 仅横图 / 仅竖图;选「横竖均可」时比值双向比较,所以 `16:9` 也会命中 `9:16` |
| 格式 | 按扩展名多选(`jpg` / `png` / `webp` …),与比例条件是**与**关系 |
| 范围 | 整个资源库 / 当前选中 / 指定文件夹 |

容差是**相对值**:`16:9 ±5%` = `1.778 ±0.089`;`1:1 ±5%` = `0.95 – 1.05`。
**容差填 0 时结果与原生精确匹配完全一致** —— 这条被单测和真实数据双重锁定。

**长宽比分布图**按 `log2(宽÷高)` 分 72 箱展示当前候选集的分布,当前条件覆盖的区间会高亮 ——
你可以先看到分布再决定容差,而不是盲调。**明暗主题**跟随 Eagle。

**多选与批量操作**

每格左上角有勾选框;**Ctrl 点**加选、**Shift 点**范围选,也可以点「全选 / 反选 / 清空选择」。
四个批量动作都作用于**当前选中的项**;没有勾选时,才作用于全部匹配(动作栏会写明目标是
「已选 N 项」还是「全部 N 项」)。改变筛选条件时会自动剔除已经不再命中的勾选。

- **在 Eagle 中选中** —— 把这批素材送进 Eagle 主窗口的选区,之后就能用 Eagle 自己的一切功能处理它们
- **打标签** —— 批量**追加**标签(幂等,见下)
- **复制路径** / **导出清单**(JSON,含 `ratio`、`nativeShape` 以及本次条件与目标)

### 打标签的语义

核心就一行判断,所以**同一个标签名不会重复打**:

```js
var tags = Array.isArray(it.tags) ? it.tags.slice() : [];
if (tags.indexOf(tag) === -1) tags.push(tag);   // 已有同名标签就不再添加
it.tags = tags;
await it.save();
```

| 情况 | 结果 |
|---|---|
| 同一个标签名,多次筛选都命中同一张图 | 只有一个该标签,**不会重复** |
| 用了**不同**标签名(如「近似方形5%」与「近似方形1%」) | 两个标签都留在图上(有意的:它们是不同条件的集合) |
| 素材原本已有别的标签 | **只追加,绝不覆盖** |

实现上会先用 `getByIds()` **分批回读**完整条目对象(每批 200 条)再保存 ——
只有完整对象才带 `tags`,拿轻量索引去覆盖保存会把素材原有标签抹掉。单次上限 3000 项。

## 三、安装

**方式 A(推荐)**:把整个 `eagle-shape-range` 文件夹放到 Eagle 的插件目录:

```
%APPDATA%\Eagle\Plugins\eagle-shape-range
```

确保 `manifest.json` 就在这一层。**重启 Eagle**,按 `P` 打开插件面板即可看到「形状范围筛选」。

**方式 B**:从 [**Releases**](../../releases) 下载 `.eagleplugin` 双击安装;
或自己构建 —— `pwsh -File tools/pack.ps1` 生成 `dist/*.eagleplugin`,
若提示脚本未签名,用 `pwsh -ExecutionPolicy Bypass -File tools/pack.ps1`。

| 依赖 | 要求 |
|---|---|
| Eagle | 4.0 build12+(用到 `item.select`);实测目标 4.0.0.42 / build 22.3.7 |
| 无需 Node / Python | 运行只依赖 Eagle 注入的 `eagle` 与 `require`;`test/`、`tools/` 仅开发用 |

首次打开会读全库并写一份索引缓存到插件目录,之后打开就是毫秒级。

## 四、性能:为什么不走 `eagle.item.get()`

| | 走插件 API 拿全库 | 本插件(v2) |
|---|---|---|
| 取数方式 | 把**每个完整 Item 对象**经 IPC 序列化 | 直接读 `images/<id>.info/metadata.json` |
| 全库耗时 | 分钟级 | **冷启动 ~1.4s** |
| 二次打开 | 每次重来 | **缓存命中 ~80ms** |
| 缩略图 | 随全量数据一起传 | 只为当前可见页 `getByIds()` 懒加载 |

实测(约 6 万条的真实素材库,58,445 条含尺寸):

```
-- cold scan (direct metadata reads) --
  items with dimensions : 58,445 / 59,928 folders
  skipped (no raster)   : 1,483
  elapsed               : 1.43s
  throughput            : 41,908 files/s
  cache written         : 5.6 MB
-- warm start (cache hit) --
  source                : cache
  elapsed               : 38 ms
```

复现:`node tools/bench-index.js "<你的资源库路径>"`

缓存写在插件目录的 `index-cache.json`,只有当条目 id 集合变化时才失效;
点「重新扫描」可强制重建。若环境里拿不到 `require('fs')`,插件会自动退回插件 API
并在状态栏说明。

## 五、实现要点

- **`js/indexer.js`** —— 直读库元数据。48 路并发、进度回调、磁盘缓存 + id 集合比对,
  缓存损坏/不可写时降级为扫描而不是报错。资源库路径按多级回退定位
  (`eagle.library.path` → 从任意条目的 `filePath` 反推 → 上次手动指定 → 短暂重试),
  全部失败时才让你手动选文件夹。
- **`js/matcher.js`** —— 纯函数匹配逻辑,零依赖,浏览器与 Node 共用,因此可以脱离 Eagle 单测。
  同时复刻了 Eagle 原生的分桶与精确比值判定,界面上「原生 ✓ / 原生漏」的标注才可信。
- **`js/plugin.js`** —— 界面与动作。缩略图按可见页分批回读;勾选只改 class 不重建 DOM
  (否则会丢滚动位置和已加载的缩略图)。

## 六、开发与测试

```bash
node test/run-all.js                              # 49 个用例
node --check js/indexer.js
node tools/bench-index.js "<你的资源库路径>"
```

覆盖范围:

1. **原生一致性** —— `nativeShape()` / `nativeCustomMatches()` 必须复现 Eagle 的判定
   (2.5 阈值、`width === height`、浮点精确比值),否则界面上的标注不可信。
2. **容差为 0 退化为原生精确匹配**;容差放宽时结果集合单调递增。
3. **真实素材库回归** —— `test/fixtures/library-sample.json`(3,908 条真实宽高,
   素材 id 已替换为合成值)断言模糊匹配严格多于精确匹配,并单独锁定 `3413×3430` 这个反例。
4. **索引层** —— 用临时仿真资源库验证:尺寸解析与非法数据跳过、并发上限、进度单调、
   缓存命中/失效(增删条目)、损坏缓存降级、缓存不可写时仍可用、从条目路径反推资源库根。
5. **界面契约** —— 每个 `$('...')` 查询的 id 都存在;依赖模块在使用前加载;
   四个批量动作都作用于选中集;格式条件真的参与过滤;`renderGrid` 必须显式传 append 标志;
   缩略图必须按 class 定位槽位;以及断言插件不会退回整库 `item.get()`。

> `test/` 里没有用 `node --test`:它会为每个测试文件派生带管道的子进程,
> 在一些受限环境里会以 `spawn EPERM` 失败。`run-all.js` 在同一进程内 require 各测试文件,
> 跑的是同一套 `node:test` 断言。

### 一个值得单独说的坑(已写成回归测试)

Eagle 的插件渲染进程开了 Node integration,所以 `<script src>` 执行时
**`window` 和 CommonJS 的 `module` 同时存在**。常规 UMD 写法:

```js
if (typeof module === 'object' && module.exports) module.exports = factory();
else root.ShapeMatcher = factory();     // ← 永远走不到这里
```

会走前面那个分支,**全局变量永远挂不上**;页面里 `window.ShapeMatcher` 是 `undefined`,
在第一次 `M.PRESETS` 访问时抛异常,界面就停在初始文案上 ——
看起来像「一直在扫描」,非常容易误判成性能问题。
`test/ui-contract.test.js` 用 Node 的 `vm` 造出「window + module 同时存在」的环境,
把这个行为锁死了。

## 七、已知限制

- **打标签是一次性快照**:之后再导入的新素材不会自动补上;要更新就再跑一次筛选再打一次
  (同名标签依然不会重复)。
- **不做横竖互换**:与 Eagle 自己的约定一致(它把 `4:3` 和 `3:4` 拆成两个选项)。
  要竖版就把目标比例填成 `9:16`。
- **缓存只按条目 id 集合判断是否失效**:若素材在**原地被替换**且 id 未变,尺寸变化不会被察觉,
  点「重新扫描」即可。
- 暂不支持「比例 + 物理尺寸」联合条件(例如「近似方形且 ≥2000px」),
  在 `js/matcher.js` 里加一条独立断言即可。
- 界面文案目前是中文。
